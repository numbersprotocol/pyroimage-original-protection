# UI 優化建議書 v2 — 原創影像主動防護（PyroImage）

> 狀態：**待 Sofia 確認**。此文件為建議，尚未修改任何程式碼。
> 範圍：純前端呈現層（`src/App.tsx` + 文案），不動 backend / 巡檢 script / JSON 資料契約。
> 產出：3-loop 深度審視（2026-07-08），以「組織使用者」視角重審目前呈現。
> 對應現況：`main` @ `0e6a481`（PR #1 已 merge）。

## 0. 審視框架：誰是「組織使用者」

第一線使用者不是工程師，而是組織的**品牌保護 / 法務 / 內容維權 / 公關 / 數位資產窗口**。
拿到 demo 連結時，心裡只有三句話：

1. 這是什麼、對我的圖有什麼用？
2. 現在保護了什麼、有沒有抓到盜用？
3. 我接下來要做什麼？

心智模型是「我的圖 / 被誰盜用 / 證據 / 下架」，不是「感知雜湊 / 候選影像 / combined distance / adapter」。

---

## 1. 三個提問的結論

### Q1 — 第一次進入期待看到什麼？
- 期待：一句話定位（E1）、現況快照（E2）、真/示範界線（E3）、明確下一步（E4）、信任訊號（E5）。
- 現況：E3 做得好（demo notice + honesty banner）；E1 資訊在但非「3 秒可掃」；**E2 在歡迎當下看不到現況數字**；E4 進主畫面後行動線變弱；**E5 首屏缺信任錨**。
- 核心錯位：歡迎彈窗解釋了「機制」（四步流程），卻沒回答「我現在的狀況」，且四步流程在 overlay 與 dashboard 重複出現兩次。

### Q2 — 繁中頁資訊是否足夠讓第一次的人會用？
- 任務 A 原創查驗 → **最大斷點**：輸入框邀請貼任意圖，但只接受已收錄樣本，貼真實圖會受挫；nav 承諾「查一張圖是不是原創」> 實際能力。
- 任務 B 疑似盜用→案件 → 大致足夠（hint 完整）。
- 任務 C 存證報告 → 價值訊號被技術欄位（hash）稀釋；「匯出」示範但像真能下載。
- 任務 D 原創庫 / 任務 E 監控通路 → 足夠。
- 跨頁：缺全站「這是誰、證據有什麼效力」；儀表板右上巡檢中繼資料太技術。

### Q3 — 有無過深/難懂字詞？
- 直接外露英文/程式碼：`registered_original · simulated`、`combined distance`、`Fixture check`、`dry_run`、大量 ALLCAPS 微標籤、時間軸中英重複。
- 專業名詞未白話：視覺指紋、感知雜湊命中、來源/轉檔命中、公開主張 CLAIM、上鏈存證/HASH、保護基準、本機指紋庫。

## 2. 優化建議（依優先序）

### P0 — 阻礙第一次理解 / 會誤導（最優先）

**P0-1 修「原創查驗」的期待落差**
- 問題：輸入框「貼上圖片網址或資產 ID」邀請使用者貼真實可疑圖，但只接受已收錄樣本 → 第一個動作就受挫。
- 建議：
  - 把「範例查驗（點一下試跑）」升為主要動作、置於輸入框之上；輸入框降級並加即時說明「示範版僅能查驗已收錄樣本，請先點範例」。
  - nav 與頁首把承諾改精準：`原創查驗` 副標由「查一張圖是不是原創」→「查驗已收錄的原創（示範）」。
  - unsupported 提示改正向：「示範版目前只認得已收錄樣本，正式版可查驗任意圖片」。
- 預期效果：第一次點最吸睛功能不再撞牆；承諾=能力，信任提升。

**P0-2 歡迎彈窗補「現況一行」、流程去重**
- 問題：overlay 只講機制不講現況（E2 缺）；四步流程 overlay + dashboard 重複兩次。
- 建議：overlay 頂部加一行現況快照（例：「已保護 N 張原創 · 目前真實侵權 0 件 · 監控 M 個通路」）；overlay 的四步流程改為精簡摘要或可收合，主要四步互動留在 dashboard。
- 預期效果：歡迎當下同時回答「這是什麼」+「我現在的狀況」；減少重複閱讀。

### P1 — 顯著影響易懂與信任（次優先）

**P1-1 首屏信任錨（E5）**
- 問題：首屏只有 logo + `PYROIMAGE · PROVENANCE PATROL`（全大寫英文），沒回答「誰做的、證據能不能用」。
- 建議：topbar 副標或 overlay 加一句「由 Numbers 提供 · 存證可上鏈驗證、可交付法務」；`PROVENANCE PATROL` 加中文「來源巡檢」。
- 預期效果：組織評估者第一眼獲得信任脈絡。

**P1-2 儀表板頭號數字改為「使用者關心的」**
- 問題：KPI「本次巡檢候選/候選」、右上「visionWebDetection · dry_run · N 來源」是工程語言（且 adapter fallback 可能顯示 `unknown`）。
- 建議：頭號 KPI 用「疑似盜用 / 真實侵權 / 受保護張數 / 已存證報告」；「候選」降級或收進次要說明；右上巡檢狀態改白話「巡檢模式：試跑（不計費）」，隱藏 raw adapter id。
- 預期效果：儀表板第一眼傳達「跟我有關」的數字。

**P1-3 存證報告傳達價值而非 hash**
- 問題：「區塊鏈憑證 HASH」欄顯示截斷雜湊字串，對使用者無意義；「匯出」像真能下載。
- 建議：欄位改顯示「可驗證」狀態 + 可點的驗證連結；示範按鈕標「匯出（示範）」。
- 預期效果：報告頁傳達「可交付、可驗證」的核心價值。

**P1-4 dashboard 保留明確主行動（延續 E4）**
- 問題：行動線在 overlay 很強、進 dashboard 後變弱。
- 建議：dashboard 頂部保留一個主 CTA（「執行一次巡檢」或「查驗一張圖」），與 topbar 動作呼應。

### P2 — 用詞打磨 / 細節（可批次處理）

**P2-1 移除中文頁的英文/程式碼外露**
- `registered_original · simulated` → 「原作命中 · 示範」
- `combined distance` → 「綜合相似距離」；`Fixture check` → 「範例查驗自檢」
- ALLCAPS 微標籤（MATCH/TOP MATCH/LATEST DETECTIONS/CHANNEL STATUS/BREAKDOWN/PROVENANCE TRACE/REVIEWER NOTICE）→ 中文為主，英文縮小或移除
- 時間軸中英重複（…SEALED 等）→ 只留中文

**P2-2 專業名詞加白話註解**
- 視覺/數位指紋 → 首次出現加「（影像的獨特特徵值，改圖也認得出）」
- 感知雜湊命中 → 「影像特徵比對命中」
- 來源命中 / 轉檔後命中 → 「原作命中／改過的原作也命中」
- 公開主張 CLAIM → 「對外宣稱狀態」
- 保護基準 → 「受保護原作總數」；本機指紋庫/已索引樣本 → 「已收錄樣本數」
- 判定線 → 「判定門檻」；零付費 API → 「本次查驗零費用」

**P2-3 卡片雜訊收斂**
- 原創庫卡片底部的指紋字串可移到憑證 modal 內，卡片正面保留作品名/作者。
